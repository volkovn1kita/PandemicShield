# Етап 2: Nextclade, правила-варіанти і новий інтерфейс

> Що зроблено і навіщо. Основи предметної області: [`DOMAIN_GUIDE.md`](DOMAIN_GUIDE.md). Куди далі: [`DIRECTION.md`](DIRECTION.md).

---

## 1. Ідея етапу

На етапі 1 ми виправили власне «ядро», яке шукає ORF і точні мотиви в білках. Але `BIOLOGY_REVIEW.md`
показав межу цього підходу: точний мотив перестає знаходитися, щойно поруч з'являється ще одна мутація.
Етап 2 перевірив це на практиці: старий мотив D614G знайшовся лише в 6 із 7 реальних геномів. У JN.3.3
поруч стоїть P621S, а Nextclade бачить D614G в усіх семи.

Тому PandemicShield не намагається написати власний алгоритм виклику варіантів. Він **оркеструє
перевірений інструмент**, яким користуються лабораторії в усьому світі, і додає те, чого Nextclade
сам не робить:
- історію зразків і запусків;
- пошук мутації між усіма зразками;
- правила сповіщень;
- інтерфейс українською.

## 2. Як тепер іде аналіз

```
Flutter ──POST /api/analyze (файл + nextcladeDataset)──► API
                                                         │ 1) стрімить файл у Parser (як раніше: вікна → Worker → ORF-мотиви)
                                                         │ 2) паралельно зберігає копію у спільний том /data/runs/{runId}/input.fasta
                                                         │ 3) кладе завдання в чергу nextclade_jobs (стійка черга)
                                                         ▼
                                        PandemicShield.Nextclade (воркер)
                                                         │ nextclade run --input-dataset /datasets/<набір> --output-ndjson …
                                                         │ читає NDJSON рядок за рядком (пам'ять не росте з кількістю геномів)
                                                         │ зберігає: клада, лінія Pango, QC, покриття, усі мутації
                                                         │ застосовує правила-варіанти → сповіщення
                                                         ▼
                                                    PostgreSQL ◄── API ◄── Flutter (сторінка «Зразки»)
```

### Чому саме так

| Рішення | Навіщо |
|---|---|
| Nextclade CLI **у контейнері воркера**, набори даних завантажуються під час збирання образу | Аналіз працює **офлайн**, дані не покидають машину. Це головна вимога клінічних і державних лабораторій |
| Версія Nextclade зафіксована (3.24.0), тег набору даних зберігається з кожним результатом | Відтворюваність: через рік можна сказати, якою версією отримано результат. Клади й лінії з часом оновлюються |
| Окрема **стійка** черга `nextclade_jobs` | Завдання не губляться, якщо RabbitMQ перезапуститься |
| Вихід у форматі **NDJSON** читається потоково | Файл на 10 000 геномів не завантажується в пам'ять цілим |
| Воркер пише в БД сам, а не через Aggregator | Результат одного запуску — це пакет (геноми + мутації + сповіщення + статус). Зберігати його транзакційно порціями простіше й надійніше, ніж розсилати тисячі дрібних повідомлень |
| Файл запуску зберігається | Можна **повторити аналіз** з новішим набором даних або після додавання нових правил (`POST /api/runs/{id}/nextclade`) |

## 3. Що з'явилося в даних

| Таблиця | Що зберігає |
|---|---|
| `SequenceResults` | Один рядок на геном: клада (`21J`), повна назва (`21J (Delta)`), лінія Pango (`AY.3`), QC (`good`/`mediocre`/`bad`), покриття, кількість замін і делецій, помилки |
| `Mutations` | Кожна мутація з координатами референсу: `A23403G`, `S:D614G`, `S:F157-`, `del:22029-22034`, `ORF7b:fs14-44`. Індекс за `Label` потрібен для пошуку між зразками |
| `VariantMarkers` | Правила сповіщень у текстовому позначенні (`S:N501Y`, `clade:Delta`, `lineage:BA.2.86*`) з прив'язкою до набору даних |
| `Runs` (+поля) | Статус Nextclade (`Queued` → `Running` → `Completed`/`Failed`), набір даних, підсумок |
| `Threats` (+поля) | `Source` (`orf-motif` чи `nextclade`) і `Variant`. Для Nextclade координати рахуються в референсі (MN908947), а не в самому файлі |

Міграція `AddNextcladeResults` коректно накочується на базу з даними етапу 1: старі сповіщення
отримують `Source = orf-motif`, старі запуски — `NotRequested`. Це перевірено на реальній базі.

## 4. Мова правил (`PandemicShield.Bio/Variants/VariantPattern.cs`)

| Запис | Значення |
|---|---|
| `S:N501Y` | Заміна амінокислоти N→Y у позиції 501 білка S |
| `S:E484` | **Будь-яка** заміна в позиції 484 (E484K, E484A, E484R…) |
| `S:F157-` | Делеція амінокислоти |
| `ORF8:Q27*` | Заміна на стоп-кодон (`*` у білку — це стоп, а не «будь-яка») |
| `A23403G` | Заміна нуклеотиду; `23403` або `A23403*` — будь-яка заміна в позиції |
| `22029-` | Делеція, що зачіпає нуклеотид 22029 |
| `clade:21J`, `clade:Delta` | Клада за кодом Nextstrain або за назвою ВООЗ («Delta» спрацює для 21A, 21I і 21J) |
| `lineage:BA.2.86*` | Лінія Pango разом із **нащадками**: JN.1 = BA.2.86.1.1, тож теж спрацює |

### Три біологічні уроки, закріплені в тестах

1. **Ту саму делецію можна записати по-різному.** Delta зазвичай описують як «E156G + del157-158», а
   Nextclade вирівнює ці ж 6 нуклеотидів як `E156-, F157-, R158G`. Білок однаковий, а позначення різні.
   Тому правило `S:E156G` **не спрацює** на Delta, а `S:F157-` спрацює
   (`Delta_described_as_E156G_does_not_match_nextclade_alignment`).
2. **Назви ліній — це скорочення.** EG.5.1 — це XBB.1.9.2.5.1, а JN.3.3 — це BA.2.86.1.3.3. Щоб правило
   «BA.2.86 і нащадки» працювало, порівнюється розгорнута назва (`partiallyAliased`).
3. **Одна мутація ≠ лінія.** D614G є в 157 зі 165 прикладів Nextstrain. Правило на неї було б «шумом»,
   тому серед стартових правил її немає. Натомість є правила зі змістом: імунне ухилення (E484K, L452R),
   ACE2 (N501Y), сайт фурину (P681R), резистентність до Paxlovid (nsp5 E166V = `ORF1a:E3429V`).

## 5. Тести

`PandemicShield.Nextclade.Tests` працює на **справжньому виході** Nextclade 3.24.0 для семи реальних
геномів з прикладів Nextstrain (Alpha, Beta, Delta AY.3, BA.2.3.20, JN.3.3, EG.5.1.16, JF.4) і однієї
занадто короткої послідовності. Файли лежать у `PandemicShield.Nextclade.Tests/Data`.
FASTA-файл можна завантажити в застосунок як демо.

Тести перевіряють:
- клади та лінії кожного геному;
- переведення координат у формат з 1 (`pos 23402` → `A23403G`);
- позиції кодонів;
- зсув рамки в JF.4;
- матрицю «геном × правило»: яке правило на якому геномі спрацьовує;
- пошук нащадків ліній;
- ігнорування правил для іншого набору даних.

Разом із тестами ядра їх **90**. Наскрізно (PostgreSQL, RabbitMQ, усі сервіси, справжній Nextclade)
перевірено:
- завантаження файлу дає 8 результатів, 967 мутацій і 13 сповіщень, і вони збігаються з матрицею тестів;
- пошук `S:E484K` знаходить Beta та JN.3.3;
- повторний аналіз застосовує нове правило P681H до старого запуску.

## 6. Інтерфейс

Перша версія нового UI мала типові ознаки «згенерованого» дизайну: кольорові смужки на картках,
бейджі на всьому, плитки з іконками, градієнти. Друга версія зроблена за письмовою дизайн-системою
[`DESIGN.md`](DESIGN.md), зібраною за принципами Linear, Vercel Geist і Nextclade Web:

- **Розділи за об'єктами:** *Запуски*, *Геноми*, *Сповіщення*, *Правила*. Лічильники стоять у навігації
  замість окремих плиток.
- **Монохромна основа.** Колір лише для змісту: клади в хронологічній шкалі (як у Nextstrain),
  сповіщення червоні, статус якості — зелений, бурштиновий чи червоний.
- **Таблиці замість карток.** Рядки по 40 px з підсвіткою при наведенні. У кожному геномі є **смуга
  мутацій**, як у колонці «Sequence view» Nextclade Web, з червоними мітками сповіщень.
- **Деталі в бічній панелі**, тож таблиця лишається видимою. Там є правила, що спрацювали, карта геному
  з підписами і білкові зміни за генами.
- **Пошук мутації** в заголовку сторінки «Геноми» працює по всіх запусках.
- **Світла й темна теми**, **УКР / EN**, вбудовані шрифти IBM Plex з кирилицею.
- Новий ендпоінт `GET /api/runs/{id}/genome-marks` віддає компактні позиції замін і делецій для смуг
  у таблиці.

Код:
- `lib/theme.dart` — токени `Palette` для світлої й темної тем;
- `lib/widgets.dart` — таблиця, мітки, карти геному;
- `lib/store.dart` — спільний стан;
- `lib/pages/*` — сторінки.

## 7. Що далі

- **SignalR** замість опитування: прогрес запуску в реальному часі.
- **Автовибір набору даних** (`nextclade sort`): файл із сумішшю вірусів розподіляється по наборах автоматично.
- **FASTQ на вході** (minimap2 + ivar → консенсус → Nextclade) і **Freyja** для стічних вод.
- **AMRFinderPlus** як другий тип воркера, для бактерій (див. `DIRECTION.md`).
- Збереження вибраної мови між запусками застосунку.
